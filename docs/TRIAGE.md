# 이슈를 어떻게 처리하나 (TRIAGE)

이슈가 들어오면 메인테이너가 **검토 → 판단 → 적용해 보기 → 결과 남기기** 순서로 처리합니다. 판단 근거는 항상 이슈에 적습니다.

## 1. 접수 (자동)

새 이슈에는 `needs-triage` 라벨과 안내 댓글이 자동으로 붙습니다([.github/workflows/triage.yml](../.github/workflows/triage.yml)).
실제 이름·번호가 들어 있으면 먼저 가리거나 삭제합니다([CODE_OF_CONDUCT](../CODE_OF_CONDUCT.md)).

## 2. 분류

| 라벨 | 뜻 |
|---|---|
| `bug` | 만들어진 페이지·생성기가 의도와 다르게 동작 |
| `device-report` | 어느 기기·OS·브라우저에서 해 본 결과(성공·실패 모두 가치 있음) |
| `enhancement` | 새 기능·개선 제안 |
| `question` | 쓰는 법 질문 → 답하고 토론으로 안내 |
| `commercial-collab` | 상업적 이용·공동 개발 제안([COMMERCIAL.md](../COMMERCIAL.md)) |
| `needs-info` | 재현에 필요한 정보 부족 |
| `accepted` / `declined` | 판단 결과 |

## 3. 판단 기준 — 다섯 질문

1. **재현되는가?** 기기·OS·브라우저와 한 일의 순서가 있고, 가짜 명단(`sample/`)으로 되풀이할 수 있는가. 아니면 `needs-info`.
2. **고칠 가치가 있는가?** 모임 총무·회원이 **저장에 성공하는 데** 또는 **개인정보 안전**에 영향이 있는가. 몇 명·몇 기기에 영향을 주는가.
3. **개발 방향과 맞는가?** [ROADMAP.md](../ROADMAP.md) 의 원칙에 부딪히지 않는가, "하지 않는 것"에 들지 않는가.
4. **가장 작은 변경으로 되는가?** 코드·안내·시험이 늘어나는 비용 대비 효과. 문서·안내 문구 수정으로 풀리면 그쪽이 먼저.
5. **안전한가?** 새 개인정보 위험(번호 전송·추적·저장)이 생기지 않는가.

- 다섯 질문에 모두 "예"에 가까우면 **수용**(`accepted`).
- 방향은 맞지만 지금 우선순위가 낮거나 정보가 더 필요하면 **보류**(이유와 조건을 적고 `needs-info` 또는 로드맵 후보로).
- 방향과 안 맞거나 위험하면 **거절**(`declined`, ROADMAP 의 어느 원칙인지 적고 가능한 대안을 함께).

## 4. 적용해 보기

수용한 이슈는 가장 작은 변경으로 **직접 적용하고 시험**합니다.

1. 브랜치에서 고치고 `tests/` 에 시험을 더합니다(가짜 값만). `python -m pytest -q` 통과.
2. 폰 화면 안내를 바꿨다면 어느 기기·OS·언어에서 확인했는지 적습니다. 확인하지 못했다면 "확인 못 함"이라고 씁니다.
3. 병합하고 [CHANGELOG.md](../CHANGELOG.md) 에 한 줄.

## 5. 결과를 이슈에 올리기

닫기 전에 **결과 댓글**을 남깁니다(수용·거절·보류 모두).

```
**결과: 수용(적용함) / 보류 / 거절**
- 판단: (다섯 질문 중 근거가 된 것, ROADMAP 원칙 번호)
- 한 일: (무엇을 바꿨는지, 커밋·PR 링크)
- 시험: (어떤 시험·기기에서 어떻게 확인했는지 — 확인 못 한 것은 못 했다고)
- 남은 것 / 대안: (없으면 "없음")
```

## 6. 지키는 것

- 확인하지 않은 것을 "됩니다"라고 쓰지 않습니다.
- 응답 목표: 첫 답은 3일 이내(주말·휴일 제외하지 않음 — 지키지 못하면 이슈에 사정을 적습니다).
- `needs-info` 는 14일 동안 답이 없으면 정중히 안내하고 닫습니다. 정보가 오면 다시 엽니다.
- 같은 내용은 하나로 합치고 서로 링크합니다.

## 메인테이너용 명령

```bash
gh issue list --repo heedonggu/group-vcard-saver --label needs-triage      # 접수된 것
gh issue view <번호> --repo heedonggu/group-vcard-saver --comments         # 내용 읽기
gh issue edit <번호> --add-label accepted --remove-label needs-triage      # 판단 표시
gh issue comment <번호> --body-file 결과.md                                # 결과 올리기
gh issue close <번호> --reason completed                                   # 닫기(거절은 --reason "not planned")
```
